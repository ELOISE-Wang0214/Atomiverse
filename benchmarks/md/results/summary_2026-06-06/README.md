# Atomiverse vs LAMMPS — benchmark summary (2026-06-06)

Consolidated, latest head-to-head of the Atomiverse MD engine against LAMMPS,
CPU and GPU, after the 2026-06-06 optimization round. The master figure
`benchmark_summary.png` is generated by `plot_summary.py`, which pulls the
latest data from the sibling result dirs (no data duplicated here):

- CPU: `../pe_opt_2026-06-06/lj_pe_weak_matched.csv`
- GPU: `../gpu_scaling_optimized/{av,lmp}_{single,multi}.csv`

## Headline

| platform | system | scale | Atomiverse | LAMMPS | AV / LMP |
|----------|--------|-------|-----------|--------|----------|
| CPU multicore (weak) | LJ      | 1 core    | 13.7 Matom-step/s | 4.6  | **3.0×** |
| CPU multicore (weak) | LJ      | 1024 cores| 2859 | 2370 | **1.21×** |
| CPU multicore (weak) | PE-melt | 256 cores | 236.4 | 229.2 | **1.03×** |
| CPU multicore (weak) | PE-melt | 1024 cores| 880  | 865  | **1.02×** |
| single-GPU (GH200)   | LJ      | 1 M atoms | 1735 | 1251 | **1.39×** |
| single-GPU (GH200)   | LJ      | 8 M atoms | 2097 | 1775 | **1.18×** |
| single-GPU (GH200)   | LJ      | 32.8 M    | 2137 | 1807 | **1.18×** |
| multi-GPU (GH200, 4) | LJ      | 64 M atoms| 2964 | 1363 | **2.17×** |

Atomiverse leads LAMMPS at **every** measured CPU core count and now leads on
GPU at large single-GPU N and across multi-GPU (single-process, NVLink P2P).

## Figure — unified template

All four panels share one encoding: **throughput** on the left axis (solid
lines, filled markers) and **memory** on the right axis (dotted lines, open
markers) — max RSS/rank for CPU, peak VRAM for GPU, both in MB (log). Blue =
Atomiverse, red = LAMMPS; one shared legend. Total atom count is on the top
x-axis (or the bottom x for the single-GPU size-scaling panel).

## Figure panels

- **(a)** CPU multicore weak-scaling throughput (LJ + PE), 1→1024 cores
  (1–4 EPYC nodes; shaded = cross-node). Weak scaling: atoms grow with cores
  (LJ ~16k/rank, PE 8k/rank).
- **(b)** CPU peak per-rank memory (fair `/usr/bin/time -v` max RSS, both
  codes). AV within ~1.5× of LAMMPS.
- **(c)** Single-GPU throughput vs system size (GH200). AV overtakes
  LAMMPS-KOKKOS above ~1 M atoms after the atom-centric per-atom-Verlet force
  path (cuda-perf).
- **(d)** Multi-GPU **weak** scaling — a fixed **16 M atoms per GPU** (total
  16M→33M→64M as GPUs go 1→2→4; total atoms on the top axis), line plot with
  per-GPU VRAM annotated. AV's single-process NVLink decomposition scales up
  (2317→2964 Matom-step/s) where LAMMPS-KOKKOS multi-GPU (MPI) flattens/drops.
  (A 64 M-atoms-per-GPU multi-run was not available — only the single-GPU 64 M
  point exists, at 78 GB VRAM; the clean weak diagonal is 16 M/GPU.)

## Method

CPU — EPYC `cpu` partition (256 cores/node), OMP=1, `srun --mpi=pmi2`. LJ
(ρ*=0.712, rc=2σ, skin 0.6, reneigh 20); PE-melt gen_pe Dreiding-UA, 20-atom
chains, NVE/limit+Langevin. GPU — single GH200 node, AV single-process
multi-GPU over NVLink vs LAMMPS-KOKKOS/CUDA; mixed precision; same LJ system.
